## Part 0 · 为什么要做分发包

视频成片之后还有一步极易被遗忘但**对触达回报最大的事**：**封面 +
简介**。在分发链上：

```
内容质量 → ... → 封面 / 标题 / 简介 → 平台推流 → 用户点击 → 观看完成率
                  ↑↑↑                ↑↑↑          ↑↑↑
              你能掌控          算法决定         内容决定
```

封面、标题、简介**是创作者能 100% 掌控的最后一公里**。其中：

- **封面是 CTR 的单一最大变量** —— 同一支视频换封面，CTR 翻倍是常态
- **标题和封面是一对** —— 封面负责"停下划动的手"（情绪 + 主体），标题
  负责"给个点进去的理由"（公式见 Part 9.3）。**两者分工不重复**：封面
  喊情绪，标题给承诺
- 简介次要，但**搜索 / 推荐算法吃这段文本** —— 关键词决定能否进 SEO
  长尾
- 章节标记对**完播率 / 用户回看**贡献明显：观众能跳到感兴趣的段
  落，平台也用它做时间轴展示

**分发包 = 5 张封面变体（AB 用） + 1 份 ≤250 字 description.md + 1 份
HH:MM:SS chapters.md**。

> 单张封面"凭审美猜测"无法预测能不能赢。**做 5 个变体跑 AB**，用真实
> CTR 数据决胜 —— 这是几乎免费的提升手段。

## Part 1 · 5 种变体策略

5 个变体共享**同一套视觉骨架**（同一个 CoverShell：左上 eyebrow / 底部
主标 / 右下 paper-grid 装饰），建立**系列识别度**。**变化只在中心舞台**。

| # | 策略 | 一句话 | 何时该用 | 何时不该用 |
|---|---|---|---|---|
| **01** | 钩子 · 疑问式 + 巨问号 | 大问号 + 一句把痛点说穿的反问 | 痛点广泛 / 受众没意识到自己有这问题 / 内容偏认知科普 | 受众已经认知到痛点（"你的 Agent 老忘事？" → 已经感同身受） |
| **02** | 钩子 · 第一/第二阶段陈述 | 两行对照的 numbered 陈述，第 2 行高亮 | 内容有清晰的"前后阶段 / 旧新方式 / 错对做法"二分 | 内容不存在天然二分（如纯介绍工具） |
| **03** | 钩子 · 数字反差 | 两张卡片 + 大数字 + arrow（如 30min → 3min） | 内容有可量化的 ROI / 时间反差 / 效率提升 | 没有量化指标硬凑数字（假数据反而扣分） |
| **04** | 视觉 · 双栏反差 | 左右栏 + 各自 icon + VS 圆心 + 两个引语对比 | 内容是"X vs Y"双概念辩证 | 内容是单线递进 / 多步流程 |
| **05** | 视觉 · 单一名词 hero | 一个英文单词占满中心（带 stroke 阴影） | 内容能浓缩成 1 个名词锚点（"Skill" / "Memory" / "Workflow"） | 主题需要 2 个以上词才说得清楚 |

> 上面 5 种是**经过验证的钩子族**。如果项目主题特殊（如纯案例 / 纯榜
> 单 / 纯工具评测），可以替换其中 1~2 种，但**保留"3 种文字钩子 + 2 种
> 视觉钩子"的混搭比例** —— 偏文字 / 偏视觉用户都能命中。

## Part 2 · 单变量原则（关键）

> **每张封面只换 1 个变量** —— 这样 AB 跑完才能判断**到底是哪种钩子赢**。
>
> 5 张共同要素必须一致：CoverShell（eyebrow + footer + grid 装饰）/
> token（颜色 / 字型族）/ 主标题文案。
>
> 变的只能是：**中心舞台的内容 + 该舞台对应的 CSS 前缀（`.cv1-` ...
> `.cv5-`）**。

为什么这么严：

- 一次换 N 个变量，赢的那张你也不知道是**哪个变量**让它赢
- 系列感不一致 = 算法无法把它们识别为"同一条内容的不同封面"，AB 数据
  失真
- 用户跨平台搜索时无法关联识别这是同一支视频的 5 张封面

**实操判断**：5 张并排看，应该一眼看出"是同一系列"，再细看才发现"中心
不一样"。如果第一眼就觉得"是 5 支不同视频"，说明 shell 没复用对。

## Part 3 · 反 AI 味反模式（封面专版）

封面比章节更怕 AI 味 —— 因为它就是一张图，没有时间维度可以遮丑。**这
些一旦出现，再贵的 token 也救不回来**：

| 反模式 | 为什么扣分 | 修法 |
|---|---|---|
| **紫粉渐变** | "AI 出图"的最强 tell；2023 年 Midjourney 的招牌 | 用项目 token 的实色 + 极轻的 accent-soft，不用渐变 |
| **emoji 在封面里** | 业余 / 个人公众号气质 | 文字钩子用文字；视觉用 SVG icon（描边、不填色） |
| **假插画 / 拟人化卡通** | 像 Notion / Linear 等 SaaS 公司的二三线营销页 | 全用 typographic + SVG 几何图形 |
| **圆角彩色 outline** | 像 PPT 默认模板 | 用 token `--rule` 的细线 + token 实色 box-shadow |
| **多行口号堆叠** | 用户 0.3 秒就刷过去，看不完 | 1 句 hero 文案 ≤ 12 字（中文） / ≤ 4 词（英文） |
| **网格 + 圆点底纹** | 像设计模板 / Behance 截图 | grid 只在右下角带 mask radial-fade 收边 |
| **字号 < 80px** | 远观（手机列表、电视屏）看不清 | hero 字号 100px 起；副标 ≥ 32px |
| **3 个以上字体家族** | 杂乱 / 业余 | 最多 2 个 family：display-cn + display-en；副标用 body |
| **左上 LOGO** | 像企业广告 | eyebrow 用细字 + 圆点（已在 CoverShell 内置） |
| **平台 watermark / 关注引导** | 平台会自动检测扣推荐量 | 完全不放，让算法判定为"原生内容" |

## Part 4 · 渲染流程

### 一次性环境准备

封面渲染复用项目自身的 dev server（已经为正片跑着的那个）。**不需要
另起 build**：

```bash
# 1) dev server 已经在跑（./start.sh <slug> 之类）
# 2) 一行命令按项目 .orientation 出对应组合的 PNG：
node <skill-path>/scripts/render-covers.mjs <slug> [--port 5174] [--ratio <r>|both]
```

`--ratio=both`（缺省）按项目 `.orientation` 自动选组合：

| 项目 orientation | 默认 ratio 组合 | 单项目 PNG 总数 |
|---|---|---|
| landscape | 16x9 + 4x3 | 5 × 2 = 10 张 |
| portrait | 9x16 + 3x4 + 1x1 | 5 × 3 = 15 张 |
| square | 1x1 + 4x3 | 5 × 2 = 10 张 |

输出位置（自动覆盖）：

```
# 单方向项目（扁平）
projects/<slug>/cover/
├── 01-hook-question.png        ← 16:9 (1920×1080，老版本兼容缺省名)
├── 01-hook-question-4x3.png    ← 4:3  (1440×1080)
├── 01-hook-question-9x16.png   ← 9:16 (1080×1920)
├── 01-hook-question-3x4.png    ← 3:4  (1080×1440)
├── 01-hook-question-1x1.png    ← 1:1  (1080×1080)
└── ...

# 双方向项目（v1.7.2+，pc/ + app/ 嵌套）—— 每个方向独立 cover/
projects/<topic>/pc/cover/                  ← render-covers.mjs <topic>/pc
├── 01-hook-question.png        ← 16:9
└── 01-hook-question-4x3.png    ← 4:3
projects/<topic>/app/cover/                 ← render-covers.mjs <topic>/app
├── 01-hook-question-9x16.png   ← 9:16
├── 01-hook-question-3x4.png    ← 3:4
└── 01-hook-question-1x1.png    ← 1:1
```

> 双方向时 **pc 和 app 的钩子文案可以不一样** —— 横版主战场 YouTube /
> B 站对"高门槛干货 / 信息密度高"的钩子接受度更好；竖版手机用户对
> "一个数字 + 一句反差"的钩子转化率更高。**单独写两套封面文案**比
> "一套通用文案两个方向都凑合"AB 效果更好。

### 5 种 ratio 与平台对照

| 平台 / 用途 | 推荐 ratio | 像素 | 说明 |
|---|---|---|---|
| YouTube / B 站 / 视频号缩略图主图 | **16:9** | 1920×1080 | 主流横屏，正片本体也是这个比例 |
| 微信公众号头图 / 旧版国内信息流 | **4:3** | 1440×1080 | 沿用纸媒版式，旧版抖音 / 知乎卡片兼容 |
| 抖音 / 视频号竖版 / Reels / Shorts | **9:16** | 1080×1920 | 手机竖屏主战场，视频本体就是这个比例 |
| 小红书首图 / Pinterest / 公众号竖图 | **3:4** | 1080×1440 | 介于 4:3 和 9:16 之间，feed 卡片更满 |
| IG / 朋友圈 / 视频号方形 | **1:1** | 1080×1080 | Square feed / Stories 兼容 |

**单变量原则提醒**：跑 AB 时同一比例之间互比（16:9 之间 / 9:16 之间），
**不要跨比例比** —— 那是两个变量一起换，结论不可信。

### 默认 = 按 orientation 自动选组合（推荐）

`render-covers.mjs` 缺省 `--ratio=both`，按项目 `.orientation` 选默认
组合（见上表）跑完一次得到完整分发包。**老项目无 .orientation = 等价于
landscape，行为与 v1.6 一字不差**：`cover/<id>.png`（16:9）+
`cover/<id>-4x3.png` 两套，文件名不变。

```bash
# 单跑某一比例（省时间）
node <skill-path>/scripts/render-covers.mjs <slug> --ratio 16x9
node <skill-path>/scripts/render-covers.mjs <slug> --ratio 4x3
node <skill-path>/scripts/render-covers.mjs <slug> --ratio 9x16
node <skill-path>/scripts/render-covers.mjs <slug> --ratio 3x4
node <skill-path>/scripts/render-covers.mjs <slug> --ratio 1x1
```

### 改了文案后

```bash
# 1) 编辑对应变体的 .tsx（如 src/covers/01-hook-question/HookQuestion.tsx）
# 2) dev server HMR 实时刷新；浏览器开
#    http://localhost:5174/?cover=01-hook-question              ← 16:9 预览
#    http://localhost:5174/?cover=01-hook-question&ratio=4x3    ← 4:3 预览
#    http://localhost:5174/?cover=01-hook-question&ratio=9x16   ← 9:16 预览
#    http://localhost:5174/?cover=01-hook-question&ratio=3x4    ← 3:4 预览
#    http://localhost:5174/?cover=01-hook-question&ratio=1x1    ← 1:1 预览
# 3) 满意了重渲：
node <skill-path>/scripts/render-covers.mjs <slug>
```

### 5 变体在竖屏 / 方形下的"单变量原则"如何继续成立

- 01 钩子 · 疑问 + 巨问号：横屏左右两列 → 竖屏单列上下叠（问号上、引语
  下）；钩子句不变，单变量仍是"用疑问句"
- 02 钩子 · 阶段陈述：数字 + 阶段名 + 动词到竖屏自动 flex-wrap 折行，
  序号 / 动词重点不变
- 03 钩子 · 数字反差：横屏 3 列（before / arrow / after）→ 竖屏单列
  上下叠 + arrow 旋转 90° 朝下；钩子"前 → 后"不变
- 04 视觉 · 双栏对比：横屏左右双栏 → 竖屏单列上下叠 + VS 圆点放中间；
  对比的两个引语和 icon 不变
- 05 视觉 · hero 单词：英文 hero 字号自动缩到 320px / 中文 1~2 字可在
  覆盖项目里再 bump 回 480px+；prefix + sub 副词不变

5 变体的"钩子"本身（疑问 / 阶段 / 反差数字 / 双栏对比 / hero 单词）在
所有 ratio 下都立住，**单变量原则不会因为换 ratio 失效** —— 你比的是
不同钩子的 CTR，不是不同比例的 CTR。

### 工作原理（怎么不撞到正片的 Stage）

`templates/src/App.tsx` 内置了 `CoverMode()`：URL 带 `?cover=<id>` 时
**直接渲染对应变体组件**，跳过 Stage / ProgressBar / AutoStartGate。
Playwright 就遍历 `COVERS` 注册表的 id 截屏：

```
http://localhost:5174/?cover=01-hook-question                ← 16:9 HookQuestion
http://localhost:5174/?cover=01-hook-question&ratio=4x3      ← 4:3  HookQuestion
http://localhost:5174/?cover=02-hook-statement               ← 16:9 HookStatement
...
```

`?ratio=4x3` 让 CoverShell 给 root 挂 `.cv-base-root--4x3` 修饰类
（在 cover-base.css 里只改 `width: 1440px`，`height: 1080px` 不变）。
所有变体的中心舞台都用 `left:100px; right:100px` 自适应宽度，**无需
为 4:3 单独改任何变体 CSS**。

> 没注册任何 cover 的项目，`?cover=foo` 会落到 unknown 分支显示"unknown
> cover id"。正片完全不受影响（不带 `?cover=` 参数走正常 Stage）。

## Part 5 · description.md 写作规范

**目标长度 ≤ 250 字 CJK**（YouTube 简介框前 1-2 行决定要不要展开；B 站 /
视频号简介 1-2 行就被折叠）。

### 4 段式（按顺序）

```
[钩子段：1-2 句]
和封面的钩子句呼应，但说法换一种 —— 不复读封面文字。
对痛点 / 反差直击。

[价值段：1-2 句]
具体说明视频在讲什么。**用「行为 + 结果」句式**，不要堆形容词。
反例：「深入浅出、保姆级教程」 → 正例：「一次 20 分钟，让 Agent 学会
你的工作流」。

[主题清单段：1-3 句]
列出视频涵盖的具体话题 / 关键节点。**用顿号或冒号串**，别用 emoji
bullet。这一段是给算法吃的关键词矿，SEO 长尾全靠它。

[受众段：1 句]
谁该看这支视频。具体一点：「适合每周有重复工作流的内部员工」比「适合
所有想用 AI 的人」强 10 倍。
```

### 反模式

| 反模式 | 为什么不要 |
|---|---|
| 开头堆形容词（"震撼 / 深度 / 干货满满"） | 算法过滤这类词 + 用户秒滑 |
| Emoji bullet（🔥 ✨ 👇 🎯） | 平台不解析 emoji 做 SEO + 显得业余 |
| 关注引导（"点关注 / 三连 / 评论区聊"） | YouTube / 视频号会扣推荐量 |
| 外链 / WeChat ID / 微信群二维码 | 平台会判违规 + 直接限流 |
| 复读视频标题 / 复读封面句 | 浪费 250 字额度 |
| 假数据（"100 万人都在用"） | 翻车成本极高 |

> **"堆形容词" ≠ "极限词 / 数字"**：被禁的是**空洞、不可兑现**的形容词
> （震撼 / 深度 / 干货满满 / 保姆级）。**被内容兜底、可验证**的极限词
> 和具体数字反而是流量爆点 —— "40 分钟全面掌握"（视频真有 40 分钟且全）、
> "一次省 3 小时"（真能省）。判据：**这句话视频本体能不能兑现**？能 = 留，
> 不能 = 假数据，删。详见 Part 9.3 / 9.4。

### 字数检查

```bash
wc -m projects/<slug>/description.md
# 中文 ≤ 250 字 = ≤ 250 chars。可以稍超到 280 但不要超 300。
```

## Part 5b · chapters.md 章节标记规范

**目标**：一份 `HH:MM:SS 章节标题` 文本，每行 1 章，可以直接复制粘
贴到 YouTube 简介 / B 站章节 / 视频号目录，平台自动识别成可点击时间轴。

### 格式（严格）

```
00:00:00 开场：钩子句
00:00:27 第一章标题
00:01:29 第二章标题
...
```

每行三段：`HH:MM:SS` + 一个空格 + 章节标题。**没有额外标点 / 序号 /
箭头**（平台只认这一种格式）。

### 硬约束（脚本会校验）

| 规则 | 来源 | 不达标怎样 |
|---|---|---|
| 第一个时间戳 = `00:00:00` | YouTube / B 站平台规则 | 平台直接拒识别，整个列表失效 |
| 每章时长 ≥ **5 秒** | 本 skill 用户约束 | 章太短观众点不准，平台也可能拒 |
| 每章时长 ≥ 10 秒（YouTube 严格规则） | YouTube 官方 | 想兼容 YouTube 需自检 |
| 至少 3 个章节 | YouTube | 少于 3 个 YouTube 不显示时间轴 |
| HH:MM:SS 格式（即使 H=00） | 本 skill 约定 | MM:SS 也能兼容大部分平台但不统一 |

### 章节起点怎么算

- 章节起点 = 该章 **第一个 step 在视频里的开始时间**
- 起点数据来源：`projects/<slug>/video-out/timings.json`（render-video.mjs
  录渲时记录的每个 step 的实测开始时间）
- 章节标题来源：`presentation/src/registry/chapters.ts` 里每章的 `title`
  字段（不是 outline.md，因为 outline 可能跟实际章节数漂移）

### 生成命令（一行）

```bash
node <skill-path>/scripts/extract-chapters.mjs <slug>
# 或在 web-video 仓库内：
node scripts/extract-chapters.mjs <slug>   # 如果 skill 软链已 install
```

脚本会：
1. 读 `video-out/timings.json` + `presentation/src/registry/chapters.ts`
2. 每章取 step 0 的时间作为起点
3. 校验：第一章是否 00:00 / 每章 ≥ 5s / 至少 3 章
4. 任一不达标 → **警告 + 继续输出**（不阻塞）；让你看到再决定改不改
5. 写到 `projects/<slug>/chapters.md`

### 反模式

| 反模式 | 为什么不要 |
|---|---|
| 手敲时间戳 | 脚本读 timings.json 是真值，手敲漂移大 |
| 用 outline 章节标题 | outline 可能跟最终代码不同步，以 chapters.ts 为准 |
| `# Chapter 1` 这种 markdown header 格式 | 平台只认裸时间戳 + 空格 + 标题 |
| 加 emoji / 装饰符号 | YouTube 解析会失败 |
| 章节过细（每个 step 都做章节） | 7 章 ≈ 一支 10 分钟视频上限。再多观众感知乱 |
| 用 outline 章节切分但跳过 hook / closing | 全章节才有时间轴。少 2 章观众看不到首尾标记 |

### 不同长度视频的章节数建议

| 视频时长 | 建议章节数 |
|---|---|
| < 5 分钟 | 3-5 |
| 5-15 分钟 | 5-8 |
| 15-30 分钟 | 7-12 |
| > 30 分钟 | 8-15 |

## Part 6 · 完工 5 件事自检

分发包（封面 + 简介 + 章节）出完后**强制走一遍**，任何一件不过关都要回炉：

- [ ] **系列感**：5 张并排截屏，第一眼能识别"是同一系列"吗？
  （CoverShell 的 eyebrow + 底部主标 + paper-grid 是否完全一致）
  - **同时检查 4:3 的 5 张** —— 缺省同时出 16:9 + 4:3，两套都要过系列感
  - 4:3 不应单独看像"被压扁的 16:9" —— 中心舞台内容应自然收紧
- [ ] **单点钩子**：每张封面的中心舞台是否只表达 1 个钩子？
  （不是 1 句话钩子 + 1 个数字 + 1 个 icon 全堆在一张上）
- [ ] **token 纯度**：grep 一下 5 个变体的 CSS，**有没有硬编码颜色
  / 字体名**？（必须全走 `var(--accent)` `var(--font-display-cn)` 之类）
- [ ] **字号够大**：hero 文字 ≥ 100px？副标 ≥ 32px？eyebrow ≥ 22px？
  （手机列表 / 远观必须看得清）
- [ ] **反 AI 味过关**：紫粉渐变 / emoji / 假插画 / 圆角彩色边框 /
  3 个以上字体家族 —— 一个都没有？
- [ ] **description.md ≤ 250 字** + 4 段式齐 + 没有 emoji bullet / 关
  注引导 / 外链？
- [ ] **chapters.md** 第一行是 `00:00:00` / 每章 ≥ 5s / 至少 3 章 / 格
  式严格是 `HH:MM:SS <title>`（无序号 / 无 emoji）？

### 一键自检命令（参考）

```bash
# 字数
wc -m projects/<slug>/description.md

# 硬编码颜色（CSS 里出现 #xxxxxx / rgb()）—— 应该一个都不出
grep -rE '#[0-9a-fA-F]{3,8}|rgb\(' projects/<slug>/presentation/src/covers/

# 5×2 = 10 张 PNG 都生成了吗（16:9 + 4:3 两套）
ls -la projects/<slug>/cover/*.png | wc -l   # 缺省应该 ≥ 10
ls -la projects/<slug>/cover/*-4x3.png | wc -l   # 4:3 应该 ≥ 5

# chapters.md 第一行必须是 00:00:00
head -1 projects/<slug>/chapters.md | grep -E '^00:00:00 '
```

## Part 7 · AB 测试方法论

封面跑 AB 是为了**用真数据决胜**，不是为了"先发出去再说"。**没跑 AB
就发了主封面 = 浪费 4 张备选**。

### 各平台原生 AB 工具

| 平台 | 原生 AB | 方法 |
|---|---|---|
| **YouTube** | ✅ 有 | Studio → 内容 → 选这个视频 → 「**缩略图测试**」（A/B/C 三张）；系统自动轮播 7-14 天给胜者 |
| **B 站** | ✅ 有 | 创作者中心 → 数据中心 → **封面优化**（试验功能，需申请） |
| **视频号 / 抖音 / 小红书** | ❌ 没有原生 | 同一支视频上传到不同的「**小号 / 分发渠道**」，每号用不同封面；对照 7 天 CTR |
| **手动 / UTM** | —— | 给视频发不同社交位（朋友圈 / 群 / Slack），每条短链带不同 UTM tag，对照点击量 |

### 决胜规则

- **样本量**：每张封面至少 **≥ 10 K 曝光**。低于 5K 数据噪音太大，结
  果不可信
- **观察期**：至少 **7 天**，避免周期性（周末刷视频的人 vs 工作日刷
  视频的人，行为不同）
- **只看 CTR**（曝光 → 点击），**不要看播放完成率** —— 完成率受内容
  影响，封面的工作只到"让人点进来"为止
- **胜者**：CTR 差距 ≥ 20% 算显著；< 20% 直接选**点击绝对值大**的那张
  （差距小说明几个钩子半斤八两，挑能多带几次点击的）

### 胜者出炉后

胜者那张设为主封面，**其它 4 张归档到 `cover/` 不要删** —— 下次类似主
题项目可以直接拿这张的钩子策略当起点。

## Part 9 · 中文流量打法 playbook（封面 / 标题 / 简介）

> **来源**：对头部中文 AI 区 UP 主（95 万粉级、单条投稿 50~1100 万播放）
> 的整墙投稿做封面 / 标题拆解，提炼出一套**高度工业化、可复用**的流量
> 公式。这套和 Part 1~8 的极简 typographic 风**是两条路线**，按内容定位
> 选一条走（见本节开头 callout）。

### 9.0 先判定位：哪类内容该用这套

| 该用流量 loud 风 | 该用默认极简风（Part 1~8） |
|---|---|
| B 站 AI 区 / 抖音知识区 / 视频号涨粉向 | 产品官方 demo / 大会 talk / keynote |
| 蹭新品发布、工具评测、教程合集 | 偏品牌调性 / 高端 / To B 场景 |
| 目标是**信息流里被点开**（CTR 至上） | 目标是**看起来高级**（不靠标题党） |
| 受众是泛 AI 爱好者 / 小白 | 受众是从业者 / 已订阅的精准人群 |

> ⚠️ **不要中间态**：半个大字 + 半个极简，两边的好处都拿不到。定位选定
> 就把那一套吃透。

### 9.1 封面构图：「左字右脸」黄金模板

头部 UP 主**几乎每张封面**都是同一套可复制模板：

```
┌─────────────────────────────────────┐
│  ┌──────────────┐                    │
│  │  四字大标题   │      [情绪主体]    │   ← 左半：半屏粗描边大字
│  │  ⬛⬛  ⬛⬛   │      😲 惊讶脸     │   ← 右半：一张瞪眼/张嘴的脸
│  └──────────────┘      (或产品拟物)  │
│   [产品 Logo]                         │   ← 角落贴 GPT/Claude/Gemini logo
└─────────────────────────────────────┘
   高饱和电影感背景（城市/太空/海洋）
```

四条硬规律：

1. **左字右脸**：左边半屏大字标题，右边一张 AI 生成/真人的**夸张惊讶脸**
   （瞪眼、张嘴、捂脸）。表情几乎只有一种情绪——"卧槽太强了"——用来
   **暗示观众"你也该震惊"**。
2. **半屏大字、1 秒可读**：标题占满半屏，缩略图里一眼读完（详见 9.2）。
3. **必贴产品 Logo**：GPT / Claude / Gemini / DeepSeek / FLUX 等，蹭热点
   + 建立"我在讲最新的东西"的权威感。
4. **高饱和电影感背景**：城市 / 太空 / 海洋 / 光效，衬托主体，强对比。

> **本 skill 的 render-covers 是纯 typographic（无照片）** —— 它能高质量
> 表达"半屏大字 + 产品 Logo（SVG）+ 强对比背景"，但**惊讶脸是照片资产**，
> 需要创作者另外提供（自己的脸 / AI 生成肖像），在后期把封面 PNG 当背景
> 板、把脸抠图合成上去。实操：① 用变体渲出"左半大字 + 右半留空"的板子
> → ② Photoshop/Canva 把脸贴右半。**纯靠代码出不了那张脸，别硬凑假插画
> 顶替**（假插画反而触发 Part 3 的 AI 味红线）。

### 9.2 大标题：四字 / 两段式拼贴

封面大字不是"介绍内容"，是**情绪钩子 + 关键词标签**。规律：

- **两段式拼贴**：把标题拆成两个词组左右或上下两块，字号占满半屏——
  `Codex｜终极教程`、`Claude Code｜全解`、`养虾｜秘籍`、`专家｜模式`、
  `霸总｜出海`、`P 图｜真神`。
- **粗描边美术字**：黄 / 红 / 绿为主，**强描边 + 强投影 + 强对比**，远观
  （手机列表）也炸。映射到本 skill：用 token 实色 + `text-shadow` 描边，
  hero 字号 100px 起（竖屏更大），**最多 2 个字体族**（Part 3 铁律不破）。
- **1 秒读完**：4~6 个字 / 2 个词组封顶。读不完的标题 = 没标题。

### 9.3 标题文案 6 大公式槽位 ★（"标题生成"核心）

视频标题（投稿标题，不是封面大字）按**槽位拼装**，一条标题叠 **2~3 个
槽位**最佳，别 6 个全堆：

| # | 槽位 | 作用 | 真实例子 | 用法 / 边界 |
|---|---|---|---|---|
| 1 | **极限词**（封顶定位） | 一句话占领品类制高点 | 全网最全 / 究极玩法 / 生图之王 / 天花板 | **必须内容兜底**，假极限 = 翻车（见 9.4） |
| 2 | **数字具体化** | 把模糊价值锚成可感数字 | 40 分钟全面掌握 / 300 回合狂测 / 1 天省 3 小时 / 爆肝 10 亿 token | 数字越具体越可信；**真实可验证** |
| 3 | **方括号承诺** | 降低点击风险、抬完播预期 | 【附完整文档】【建议收藏】【小白教程】【实测对比】 | 给"点进去能拿到什么"的确定性；承诺要兑现 |
| 4 | **悬念 / 反差钩子** | 制造认知缺口逼点击 | 假如 AI 消灭了全人类，只剩你一个人… / 一天 60 集？！ / xx 亿？ | 反差越大越钓，但别标题党到内容接不住 |
| 5 | **身份代入** | 圈定"这说的就是我" | 中老年用 AI / 教父母学会 / 小白也能 / 建议转发给全家人 | 越具体的人群越容易自我代入 |
| 6 | **情绪递进** | 蹭系列 / 蹭迭代的情绪势能 | 又变强了？！ / 太卷了 / 更猛了！ | 适合连续追品类更新的系列 |

**拼装范式**（2~3 槽叠加）：

```
[极限词] + [主题] + [方括号承诺]
  例：全网最全！40 分钟全面掌握 Codex～【附完整文档】   ← 极限+数字+承诺

[悬念反差] + [主题]
  例：一天 60 集？！起底"AI 短剧"出海的捞金秘籍【全流程拆解】

[身份代入] + [极限词]
  例：中老年也能用的 AI 专家～【建议转发给全家人】
```

> **标题 ↔ 封面分工别重复**：封面大字喊**情绪 / 主体词**（`专家｜模式`），
> 标题给**承诺 / 数字 / 方括号**（`小白也能拥有的"AI 专家"【建议收藏】`）。
> 两个都喊同一句 = 浪费一半曝光面积。

### 9.4 简介（description）的流量化角度

在 Part 5 的 4 段式骨架上，套流量风时这样调：

- **钩子段**用 6 公式里的 **悬念 / 反差 / 身份**起手，别用形容词起手。
- **价值段**塞 **真实数字 + 方括号承诺**（"一次看完，附完整文档"），
  这段同时是 SEO 关键词矿。
- **极限词 / 数字一律走"可兑现"判据**（Part 5 新增 callout）：视频本体
  兑现得了就留，兑现不了就是假数据，删。
- Part 5 的所有反模式（emoji bullet / 关注引导 / 外链 / 假数据）**在流量
  风里照样禁** —— 平台扣量规则不分美学。

### 9.5 两套美学共用的铁律（流量风里也不许破）

流量 loud 风放开了"大字 / 高饱和 / 极限词"，但下面这些 **Part 3 红线照旧**：

| 仍然铁律（两套都禁） | 流量风里**放开**了的 |
|---|---|
| 紫粉渐变（最强 AI tell） | 高饱和背景 / 强对比配色（用实色，不用紫粉渐变） |
| emoji 进封面 / 进简介 bullet | 半屏巨字 / 粗描边美术字 |
| 假插画 / 拟人化卡通顶替真主体 | 真人 / AI 肖像照片（后期合成，不是代码假画） |
| 圆角彩色 outline（PPT 默认款） | 产品官方 Logo 贴角 |
| 3 个以上字体家族 | 极限词 + 数字 + 方括号承诺（**可兑现**前提下） |
| 平台 watermark / 关注引导 / 外链 | 一种统一情绪表情（"震惊脸"族） |
| 假数据 / 不可兑现的极限词 | —— |

> 一句话：**流量风换的是"喊话的音量和姿势"，不是"诚信和品味的底线"**。
> 红线那一列任何一条出现，再炸的封面也救不回推荐量。
