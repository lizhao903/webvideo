# 章节开发指引（每章开发必读）

---

## 这是视频，不是 PPT

正在做的是**视频网页** —— 讲者点击 + 口播 + 录屏发出去给观众看。
判断每一步做对没有，标准非常朴素：

- **不像 PPT** —— 观众感觉是在看视频，不是在看翻页幻灯（页面中不得包含页眉页脚，突出主视觉元素）
- **看起来舒服** —— 配色、字体、节奏都让人放松，不得出现大量的纯文字、不得出现字体太小的文字
- **有视觉冲击** —— 画面在演事情，不只是文字堆砌，不得一次性全部罗列所有元素，关键元素随进度逐步推进展现

---

## 必须用 CSS / SVG / Canvas / JS 大胆绘制视觉演示

> **这是底线。**
>
> 每一章都至少要有 1~2 处"动起来的图 / 演示元素"。
> **整章只有纯文字 = 验收不过 = 回去重做。**

视频感最强的来源 —— 用户**看见**了被讲解的东西在屏幕上演给他看：

- 数字在递增 / 横条在生长 / 排名在交换
- 流程节点依次点亮 / 连线自绘
- 对比被一刀切开 / 聚光灯扫过 / 形状在变形
- 粒子聚拢成形 / 噪声背景流动 / 字符雨下落
- 模拟终端交互
- 模拟 AI 对话窗口
- 模拟文件目录树

**怎么组合发挥都行 —— 但每章必须用，不允许整章纯文字。**

---

## 逐步揭示，禁止一次全展示

整页内容由**全局 `step` 计数器**驱动 —— 点击空白处或按 → 键推进
一步。设计每一步时心里要默念：**这一步演什么，下一步演什么**。

**最重要的一条**：

> 当口播在说"第一是 X、第二是 Y、第三是 Z"这种**清单 / 列表**时，
> **严禁**一个 step 把 X / Y / Z 全部 stagger 上来。

正确做法：

- 一项 = 一个 step
- X 只在它自己的 step 里独自亮起
- 讲到 Y 时，X 灰化保留作上下文 + Y 亮起
- 讲到 Z 时，X / Y 都灰化 + Z 亮起

**判断标准**：讲者会一个一个念出来吗？会 → 必须逐个揭示。

---

## 内容取舍：抓重点，不要原文搬运

视频是**音 + 画**：

- **口播**负责把信息线性讲清楚
- **画面**负责把节拍重点放大、节奏感拉出来

每个 step 屏幕上只挂这个节拍**最值得放大的 1~3 个东西** —— 一个
hero 标语 / 一个数字 / 一组对比 + 必要的视觉演示。

不要试图把原文每个字都搬上去。那是论文阅读，不是视频。

---

## 双源：节奏跟口播稿，细节回原文章

> **节奏 / 顺序 / 节拍切分** 跟 **`script.md` 口播稿** —— **关键顺序不能乱**。
> **画面细节 / 数据 / 引用 / 案例** 回 **`article.md` 原文章**抽。

`outline.md` 已经在每章首段抽了「信息池」做参考。但**实现章节时
也必须回去翻 `article.md` 本章对应段落** —— 那里有比口播稿多得多的
细节（具体数字、引用原话、案例维度、出处时间）。把这些挂到画面上，
让**画面信息密度 > 口播信息密度**。

> **如果你只用了口播稿的内容做章节** —— 屏幕等于把口播打字打了一遍
> —— 那就是 PPT，不是视频。
>
> 章节实现一定要回原始文章抽细节，不要嫌麻烦。

---

## 字体 / 配色 / 动画 / 留白 —— 视频演示基本审美

视频观众离屏幕远、注意力浮动，所以：

- **字号要大** —— hero 文字至少 80px 起，远观也能看清
- **留白要多** —— 舞台四边都要让出大留白，画面不要塞满
- **配色要舒服** —— **颜色和字体家族必须用主题 token**（保证换主题不破）；
  字号 / 间距 / 时长这些章节按内容自由发挥（详见下方「代码层最小约束」）
- **动画要舒服 + 炫酷** —— 出现得干净利落，停下来不抢戏；炫酷靠
  **设计巧思**（内容驱动的演示动画），不靠**速度暴力**或**密集闪烁**

## 手机端可读字号下限（1080p 视频上 B 站 / 抖音手机看）

> **场景**：哪怕舞台是 1920×1080 在电脑上看着很合适，B 站 / 抖音 / 视频号的
> 主战场是手机（屏幕宽 ~360pt，视频在 list 里更可能只占半屏）。**桌面看着
> 还行的 18px 字到手机就糊成一坨**。视频网页字号必须按"手机能不能看清"打底，
> 不是按"我的 Retina 显示器好不好看"打底。

**实战教训**：MLX 系列前几集首版很多 10-22px 字号在手机端 1080p 视频里完全
不可读 —— 必须按下面的阈值表逐项过。

| 元素 | 横屏下限 | 横屏推荐 | 竖屏 / 方形下限 | 竖屏 / 方形推荐 |
|---|---|---|---|---|
| 中文正文 / 长副标 | **≥36px** | 40-48px | **≥40px** | 44-56px |
| 中文短标语 / chip / label | **≥32px** | 36-44px | **≥36px** | 40-48px |
| 英文 caption / 路径角标 | **≥30px** | 32-36px | **≥32px** | 34-40px |
| 代码块（等宽） | **≥28px** | 32-36px | **≥32px** | 36-40px |
| 数据 hero 数字 | **≥80px** | 100-180px | **≥80px** | 120-220px |
| 章节标题 | **≥60px** | 72-96px | **≥72px** | 84-112px |
| 章节序号 / 进度小字 | **≥24px** | 28-32px | **≥28px** | 30-36px |
| SVG 内 chart annotation | 例外 | 12-16px 可 | 例外 | 14-18px（**仅限**图表内坐标 / tick / 节点 label） |

**绝对禁区**：
- **横屏**：**< 24px 的任何文字必须改**（SVG annotation 标注除外）
- **竖屏 / 方形**：**< 28px 的任何文字必须改**（更严，因为竖版在手机
  feed 里更可能只占半屏一半）—— SVG annotation 例外但下限提到 14px

看到 `font-size: 10px` / `12px` / `14px` / `16px` / `18px` / `20px` / `22px`
出现在横屏 CSS 里 = 当场红线，回去 bump。竖屏 / 方形多一档红线
`< 28px`（含 24px / 26px）。

> **怎么自检**：把 1920×1080 的舞台缩到 360px 宽（约 5.3× 缩小）看 ——
> 36px 中文正文会缩成约 6.8px，刚好是手机看 list 时勉强能认出的下限。
> 30px 以下不行就是不行，**不要自我安慰说"虚化一下也能猜出来"**。

## 竖屏 / 方形排版要点（**当项目 .orientation ≠ landscape 时必读**）

竖屏 / 方形项目不是把横屏内容压扁。**布局轴向 / 节奏 / 单 step 文案密
度全部要重做**。下面是六条硬约束：

1. **手机安全区上下边距更厚**：竖屏 1080×1920 上下各让 ≥ 120px 给 chrome
   (notch / dynamic island / 进度条 / 评论入口) 不抢戏；scaffold 注入的
   `--stage-pad-y: 120px` 已经收紧，章节代码继续在 padding 上加 ≥ 40px
   元素到边的呼吸空间。方形 1080×1080 上下 72px 即可。

2. **单列优先**：横屏的 `grid-template-columns: 1fr auto 1fr` 三列对比
   到竖屏直接换成单列上下叠，**不要硬塞**（1080 宽容不下两张大卡片 +
   中间 VS 圆点）。封面 base CSS 已经提供 5 变体的 `.cv-base-root--9x16`
   等 override 作为参考。

3. **动画方向语义**：竖屏 / 方形里**Y 轴是天然主轴**，进入 / 退出动画
   优先用 `translateY` / 高度生长 / 上下蒙版扫过；横屏惯用的左右 wipe /
   滑动到竖屏会显得违和。chip / list 项进入也优先从下向上浮起。

4. **单 step 文案更短**：手机 list 里视频卡片只占 ~360pt 宽 × ~640pt 高
   缩略图，文字越短越锐利。**竖版 step 文案上限 ~20-30 字（中文）**，
   超出就拆 step；横版的 50-80 字段落到竖版必须拆 2-3 step。

5. **章节数 / 总时长**：
   | orientation | 总时长典型 | 章节数典型 | 单章 step |
   |---|---|---|---|
   | landscape | 3-8 分钟 | 6-10 章 | 5-8 step |
   | portrait  | 30-90 秒 | 4-6 章 | 3-5 step |
   | square    | 30-60 秒 | 3-5 章 | 3-4 step |

6. **不复用横版章节代码**：哪怕主题颜色 / token 完全一样，竖版 / 方形
   **章节 tsx / css 要重写**。横版 hero 数字 180px 在竖版可能就要 220px
   才镇得住中心；横版 96px 章节标题在竖版要 84px 收回；横版的 3 列
   `card-grid` 在竖版要重排成 1 列。把横版 tsx 直接 `cp` 到竖版项目里
   90% 会出现"元素出血 + 字号偏小 + 节奏失衡"三连。

## 避免 AI 味

AI 生成的网页有几种共有的"视觉指纹"，**全部不要**：

- 紫粉 / 蓝紫对角渐变背景
- 圆角卡片 + 彩色左边框装饰
- 渐变按钮 + 大圆角药丸
- emoji 当图标用
- 假数据 / 假 logo / 假"X 万用户"
- 整章 N 步用同一种入场动画（全场 fade / 全场 blur）
- 每步都挂 ken burns / 光晕呼吸 / 持续闪烁
- 每屏右下角都挂 mono 角标 / 序号

缺的东西**承认缺** —— 用 placeholder 占位卡（一张写着"image · 16:9
描述"的卡片，按真实比例留位）。**不要**用 emoji 凑、不要找无关图凑、
不要编数字。**没有就承认没有**，比 fake 强一百倍。

## 框架已经搭好的部分（理解就好，不需重写）

- **项目方向二选一的固定舞台 + scale fit**：内容设计在 STAGE_W × STAGE_H
  （横屏 1920×1080 / 竖屏 1080×1920 / 方形 1080×1080，由 scaffold 时的
  `--orientation` 决定，落到 `src/stage.config.ts` 的 `ORIENTATION` /
  `STAGE_W` / `STAGE_H` 常量）。外层 transform scale 缩到任何视口，外围
  letterbox 留黑 —— **没有响应式断点**，章节代码也**只对一种方向负责**
- **舞台居中 + 大留白**：横屏四边至少 80px 安全区；竖屏 / 方形按 base.css
  的 `:root[data-orientation]` 选段调过的 `--stage-pad-x` / `--stage-pad-y`
  走（竖屏左右 60 上下 120 / 方形 72 / 72）
- **隐形进度条**：屏幕底部默认完全透明，鼠标悬到底部边缘才出现，
  支持点击跳转章节（录屏时摄像头看不到任何 chrome 控件）
- **全局 step 驱动**：点击舞台空白处 / 键盘 ←/→ 推进；章节是 `step`
  的纯函数，没有定时器、没有命令式状态

## 代码层最小约束

不能踩的红线，其它怎么写都行：

### 必须用 token（换主题不破的底线）

- **颜色**：`--shell` / `--surface` / `--surface-2` / `--surface-3` /
  `--text` / `--text-2` / `--text-mute` / `--text-faint` / `--rule` /
  `--accent` / `--accent-soft` / `--accent-glow` ——
  **禁硬编码 hex / rgb / 颜色名**
- **字体家族**：`--font-display-cn` / `--font-display-en` / `--font-body`
  / `--font-mono` —— **禁硬编码字体名**
- **主题性格签名**通过 primitive class 自动接入，**不要在章节 CSS 里
  重定义它们**：
  - `.hero-num`（hero 数字风格 —— 主题决定衬线 / 等宽 / 粗黑）
  - `.rule`（分割线 —— 主题决定 1px 实线 / 4px 实线 / 2px 虚线）
  - `.card`（卡片 —— 主题决定圆角 + 阴影性格）
  - `.stage-frame`（舞台底色 / 圆角 / 阴影 / 装饰图案 / vignette
    全自动，章节什么都不用做）

### 可硬编码 / 可 token，按内容自由（解锁章节自由设计）

- **字号**：想要 80px 就写 80px，想用 `var(--t-h1)` 也行
- **间距 / padding / margin**：按画面节奏写具体值
- **动画时长 / 缓动 / keyframe**：按动画意图写具体值
  （**节奏气质**参考 `theme.json` 的 `mood` —— 慢主题别写 200ms 的快动画）
- **边框宽度 / 非性格圆角 / 字距**：随手写
- **gap / grid 布局尺寸**：按画面构图写

### 其它工程红线

- 不用 `setTimeout` / `setInterval` 驱动动画 —— 用 CSS keyframes
- 章节内的可交互元素（按钮 / 自定义控件）加 `data-no-advance`，
  否则点了会被舞台误推进 step
- 章节代码物理隔离：每章独立文件夹、独立 CSS 类前缀，不跨章 import

### TS/TSX 字符串里的中文双引号（**踩过两次的坑**）

JavaScript 字符串字面量用 `"…"` 包外层时，**字面量里**再写裸的中文双引号
`"…"` —— 即使是中文标点 —— 在某些 Vite / TypeScript 解析路径下会被当成
字符串结束符提前截断，**dev server parse error** 直接挂掉。`narrations.ts`
里的口播文本 + `<Chapter>.tsx` JSX 里硬塞文案最常踩这条。

**实战教训**：MLX 系列 5 集出错 2 次（E5 narrations.ts 4 处 + Recap.tsx
1 处），每次都是 dev server 红屏，定位还得翻 stack trace。

**修法**：

- ✅ **推荐**：用 typography 中文标点替代裸 `"…"` —— `「…」` / `《…》` /
  `'…'` / `—…—` / `······`。视觉气质比 ASCII 引号好得多。
- ✅ 退而求其次：外层用反引号 `` `…` `` 包，里面随便用 `"…"`
- ✅ 实在要在 `"…"` 字面量里写双引号：转义成 `\"…\"`
- ❌ **禁**：`"他说"不知道"，然后离开。"` —— 这是错误写法

**code review 优先扫描**：每章完工 + 提交前 `grep -nE '"[^"]*"' src/chapters/<id>/`
看一眼 narrations.ts / Chapter.tsx 里有没有裸中文双引号。

### chip / tag / pill 用 em padding（**不是 px**）

> chip / tag / badge / pill 这类"小标签 + 背景色块"元素的 `padding`
> **必须用 em 单位**，不能写死 px。

**实战教训**：MLX 系列首版给 chip 写 `padding: 4px 10px; font-size: 12px;`，
后来按手机字号阈值把 chip bump 到 32-36px —— **padding 不动 → 字号 line-height
（约 45px）已经超过 4px 的上下 padding，文字直接从 bg 色块顶部和底部"出血"
出来**，视觉上像没穿衣服。

**修法**：

- ❌ 反例：`padding: 4px 10px; font-size: 12px; line-height: 1;`
  （bump font 时 bg 色块不会跟着长，文字会戳出 bg 外）
- ✅ 正例：`padding: 0.4em 0.9em; font-size: 32px; line-height: 1.4;`
  （`0.4em ≈ 12.8px` 跟字号同步缩放，line-height 给文字呼吸空间）
- 推荐 `line-height: 1.4 ~ 1.5`，避免上下贴 bg 边
- **章节内常规正文 / hero 标语**可以保留 px padding（不是 chip 类元素）

### 代码块用 `white-space: pre + overflow-x: auto`（**不要 pre-wrap**）

> 章节里要出现的代码块（`<pre>` / `<code>`）—— **必须**保持原始换行
> + 超宽横向滚动，**禁**自动换行 / 强切。

**实战教训**：MLX 系列首版代码块用 `white-space: pre-wrap; word-break: break-all`，
中英文混排时英文 token 被无情切碎 —— `mx.metal.is_available()` 被切成
`mx.met` / `al.is_available()`，观众根本看不懂这是什么 API。

**修法**：

```css
.xx-code-block {
  white-space: pre;           /* 保持源代码原换行，不自动 wrap */
  overflow-x: auto;           /* 容器太窄时横滚，不强切 */
  max-width: 1700px;          /* 在新的 stage padding 下接近极限 */
  font-size: 32px;            /* 见手机字号阈值表 */
  font-family: var(--font-mono);
}
```

- ❌ **禁**：`white-space: pre-wrap` + `word-break: break-all` /
  `overflow-wrap: anywhere`（这俩任何一个出现在代码块上 = 红线）
- 代码源就是太长？三条路：
  1. **源代码手动换行**：在 TSX 里用模板字符串拆行（保持 token 完整）
  2. **改成 chip-style 切片展示**：把 API 调用拆成一颗颗 chip / 步骤卡
  3. **缩短样例**：视频不是 API doc，只演核心 token 就够
- **每章必须有 `narrations.ts`**（与 `<Chapter>.tsx` 同目录）：
  - 数组长度 **=** 章节代码里 `if (step === N)` 出现的最大 N + 1
  - 每个元素 = 一个 string，该 step 要播的口播文本（来自 `script.md`
    对应段，**语义一致**——可微调标点 / 断句以适配 TTS，但不能漏关键短语）
  - 完全无音频的过场 step 用空串 `""`，Auto 模式会按字数估时撑过
  - **TTS 友好文本**（要合成音频时硬性）：narration 文本会原样喂给 TTS，
    而 TTS **看字面读音**——裸多音字 / 缩写 / 单位符号会被读错。三类必清：
    多音字补全成词（`调 skill`→`调用 skill`、`重跑`→`重新跑`），缩写还原
    全称（`t2s`→`文本转语音`、`LLM`→`大语言模型`、`ROI`→`投资回报率`），
    数字单位换中文词（`1.4s`→`1.4 秒`、`200ms`→`200 毫秒`、`$100`→`100 美元`）。
    完整规则 + 多音字清单见 [`SCRIPT-STYLE.md`](SCRIPT-STYLE.md)「TTS 友好文本」
  - 这是**音频合成 + Auto 模式自动推进的唯一真相源**，写错或漏写
    会让录屏对不上嘴
- **动画时长必须 ≤ 该 step 的口播时长**——Auto 模式严格按音频结束推进，
  没有"等动画跑完"的兜底。动画太长 → 三选一：**写更长口播 / 拆 step
  / 调动画速度**。详细机制见 [`AUDIO.md`](AUDIO.md)

## 完工自检（写完每章**强制**执行，不可跳过）

> ⚠️ **硬性流程**：章节实现完成后**必须**走完下面的自检 → 修复 → 汇报
> 三步。**禁止**"实现完成 → 直接汇报给用户"。
>
> **执行方式**（按能力降级）：
>
> 1. **优先 Agent Teams**：开一个独立的 reviewer agent，传入本章代码路径
>    + 本文件 Part「完工自检」清单，让它**逐项核查 + 出结论**（哪几条
>    pass / 哪几条 fail + 证据）。
> 2. **其次 subAgent**：当前 agent 没有 Teams 能力但能开 subagent，用 subagent
>    走同样的流程。
> 3. **都没有**：当前 agent 自己**严格逐项**核查，不允许目测一遍就放行。
>
> **拿到自检结论后**：先按 fail 项**改完代码**，然后再向用户汇报"做完
> 了 + 自检结论 + 改了什么"。**直接拿原始结论汇报但不修复 = 违规**。

写完一章 + 在浏览器点完一遍后逐项过：

- [ ] **每章至少 1~2 处 CSS / SVG / Canvas / JS 视觉演示** —— 没有 = 回去补
- [ ] **不同 step 的主导动作不一样** —— 全章一种动画 = 回去重做
- [ ] 字号大、留白舒服、配色舒服
- [ ] **手机端字号阈值过线** —— 横屏没有 < 24px / 竖屏 / 方形没有 < 28px
      的正文（SVG annotation 除外）；正文 ≥ 36px (横) / 40px (竖方) /
      chip ≥ 32 / 36 / 代码 ≥ 28 / 32 / hero 数字 ≥ 80。**grep
      `font-size:` 看一遍**，按当前 orientation 的阈值核验，有违规当场
      回去 bump
- [ ] **orientation 一致性** —— `.orientation` 文件、`stage.config.ts`
      的 `ORIENTATION` 常量、章节代码的字号 / 留白阈值三者方向一致。
      `cat presentation/.orientation` + `grep ORIENTATION presentation/src/stage.config.ts`
      两个值必须对得上
- [ ] 清单 / 列表逐个揭示，**1 项 = 1 step**
- [ ] 画面信息比口播稿多（回了原文章抽细节挂上来）
- [ ] 没有紫粉渐变 / 圆角彩色边框 / emoji / 假数据 / 假 logo
- [ ] 缺的素材用 placeholder，不是 fake
- [ ] **颜色和字体家族全部走 token**（无硬编码 hex / 字体名）；hero 数字
      / 卡片 / 分割线 / 舞台用 primitive class 接入主题性格 —— 这两条不
      达标 = 换主题就破
- [ ] 章节交付时**主动告诉用户**："本章还缺这些素材"
- [ ] 禁止出现小号字体，大量纯文字（出现后必须回去改）
- [ ] 禁止出现任何形式的页眉页脚，仅展示关键内容（出现后必须回去改）
- [ ] **`npx tsc --noEmit` 通过** —— 不通过禁止汇报"做完了"
- [ ] **dev server 启起来无 parse error** —— 重点扫 `narrations.ts` /
      `<Chapter>.tsx` 里有没有裸中文双引号 `"…"`（用 `「…」` / `'…'` 替代，
      或转义为 `\"…\"`），有 = 立即修
- [ ] **chip / tag / pill 的 padding 全用 em** —— grep
      `padding: \d+px \d+px` 在 chip/tag/badge 类元素上 = 红线，改成
      `padding: 0.4em 0.9em; line-height: 1.4;`
- [ ] **代码块 `<pre>` 用 `white-space: pre + overflow-x: auto`** —— 
      不允许 `pre-wrap + word-break: break-all`（会切碎英文 token）

      未跨章 import，未修改 `chapters.ts` 之外的共享文件
- [ ] **`narrations.ts` 存在**且 `narrations.length` === 章节代码里
